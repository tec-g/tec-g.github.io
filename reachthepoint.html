battle

my favorite thing about the battle system is that i dropped it completely. while it held structural depth and decently implemented, usability was abyssmal. core reason behind it was resources. they were complicated, that could cover EVERY POSSIBLE interaction.



this tree of resource was hard to manage and didn't even cover all possible interactions. so it would probably have to be even bigger.

making these kind of resources is a bad idea. when you want to add another status effect, you need to create another resource. and when you need to create an existing status effect with different value, you need to create another resource. same goes with actions.

bad usage of resources creates so much bloat in your file system and editor. you may even create identical resources. creating built-in resources (resources which are stored directly in the scene), causes scenes to load slower.

a better way to do a skill, whould be just creating skill function under the character. i litteraly don't see any downsides to that. also, i haven't developed new status effect systems, but it would probably be a RefCounted object that would be built in the skill function

anyway, another interesting thing is how i saved these routes.
a bit of context, there are 24 paths to pick from. when players ends their current route, it becomes locked while remaining 23 paths do not reroll. paths reroll every cycle, not every run. so there should be a way to store paths between multiple runs.

since path is Array[int], i can staticly store a dictionary with keys being index of the path and value being Array[int] belonging to that route. index of the path, that player currently traversing could also be stored staticly, giving an easy way to get active path anywhere.
