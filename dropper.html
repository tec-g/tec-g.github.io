Dropper

solo project | godot

frame-by-frame | turn-based | fighting game

this was my graduation project.
essentially a 3D port of YOMI Hustle mechanics.

core idea of Dropper and YOMI Hustle is to make it possible for a human to perform incredibly precise actions, which are only seen in movies.

to achieve that you stop the time when any of the character is ready to act.

while this approach doesn't have the same drive as common fighting games or hack & slash, it turns a game from button mashing to quick tactical thinking. it rewards player's skill in a different way with the similar level of excitment

development

but how you stop time? how do you even handle something, that can pause at any moment? my solution includes two parts, first of which is a frame counter

initially i wanted to actually pause. godot has a way of stopping script execution. it would handle a lot of annoyances (which i will cover later) by itself. but it obviously makes it harder to interact with game elements. there may be a way to do it like that, but i didn't have time to work in this direction. so i landed with counting frames myself.


which brings me to the second part of solution. how do you even make a skill?

imagine you want to add a sword combo for your hack & slash/fighting game.
slash -> step back -> pierce -> double slash
you create your skill function and character does the combo with a single click.

but now you want this combo to be a series of inputs. so you wait for player's inputs.
but what if player doesn't press anything for a while? you need to add check for that.
what if player gets inturrepted? you now need to check for that too

and these "what if" questions keeps piling up, not to mention specifics of my game. i needed a robust solution, which can handle any situation modulary.

so i started calling skill function every my frame and parsing refence frame. skill looks at reference frame and, based on it, does something or nothing. you gain full control of the game flow. (as a bonus, it makes replay recording easier)

implementation

this is how i build my own way of implement anything that could be called a skill in video games.
i start out with a base class of something that has/can have a skill.

extend the base class and add skill function to the collection

in godot, you can store functions (Callable) in variables just like any other Object or Variant.
this is why i love this method. easy and an interesting way to interact with the engine.

controllig

there was an interesting problem with controling characters. in YOMI Hustle, when skill needs omni-directional input, it uses a special controller. distance from center is velocity/distance and angle is direction. there are several forms of it, but all with the same purpose behind it. Dropper addopted this method, but in 3D there is two angles that form direction. my solution was to imagine this controller as a flat projection of the sphere, where inner portion is pointing down and outer portion pointing up. it loses velocity/distance control, but it could be addded as a simple slider.

there was another way of implementing it. create two of these controllers. one controls direction and motion of XZ plane, other on XY plane. but i do not see any advantages of this option over the other and viceversa. to me this is just individual preference. they both could be implemented with a toggle to switch between them.

other controls did not require any kind of special solution.
